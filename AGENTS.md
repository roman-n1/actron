# Actron: правила работы

Канон для Codex, Claude Code и других агентов. Инструкции пользователя имеют приоритет.
Адаптировано из `kmp_messenger_2/AGENTS.md` и его проектных skills (2026-10-24).
Правила мессенджера, его инфраструктура и внутренние справочники сюда не переносятся.

## Рабочий цикл

В начале новой задачи прочитай и примени [Light-цикл](skills/lite-task-workflow/SKILL.md).
Уточнение продолжает текущую задачу. Обычный запрос на изменение разрешает реализацию;
отдельный ордер, Tacticum, автоматическая делегация и повторное «ок» не нужны.
Не делай commit, push, публикацию или внешние записи без поручения.
Сохраняй незакоммиченные изменения пользователя; не очищай кеши без диагностики.

При ответе на вопрос применяй [critical-thinking](skills/critical-thinking/SKILL.md).
До выбора ответственности, API, состояния, зависимостей или жизненного цикла прочитай
[high-cohesion-low-coupling](skills/high-cohesion-low-coupling/SKILL.md) и назови
применённое правило в первом сообщении с проектным решением.

## Проектирование

- Один владелец факта; производные значения вычисляются из него. Не копируй mutable state
  между Store, плагинами, chart и tooling ради удобного доступа.
- Публичный редюсер — только наша StateChart Machine; произвольный `when`-редюсер и старый
  Store DSL не поддерживаются. `createRuntimeStore`/`StoreBuilder` — внутренний API модулей.
- Core содержит механизм Store и контракты, не Compose, logging, persistence приложения
  или statechart. Направление зависимости — от адаптеров к core.
- Общая логика — commonMain, платформенные детали — за контрактом либо expect/actual.
  Создание и запуск корутин, родительские Job, отмена и владение ресурсами — часть контракта.
- GRASP и SOLID применяются по смыслу: выделяй целую ответственность, а не файл ради LOC.
  Не вводи interface/Factory/UseCase/Registry без текущего потребителя или точки вариативности.
- Время, случайность и ID, влияющие на результат, управляй параметрами/зависимостями.
  Сохраняй атомарность, порядок событий и границы блокировок при переносе кода.
- Сохраняй WHY/ПОЧЕМУ и принятые ADR. Новые nullable API, `!!`, `lateinit` и optional wrappers
  запрещены [политикой отсутствия](doc/guides/absence-policy.md).
- Публичные Kotlin/JVM/klib API и форматы записей — контракты. Чистый рефакторинг не меняет
  API dumps. Намеренное изменение поверхности требует проверки потребителей и `apiDump`.
- В этой библиотеке есть намеренные Registry для обработчиков и DSL: не запрещай их по имени.
  Проблема — глобальный изменяемый посредник без владельца, а не слово в названии класса.

## Compose и presentation

- Прочитай [Compose presentation](skills/compose-presentation/SKILL.md) до изменения UI.
- Compose рисует готовое решение; правила, filter/sort/форматирование — mapper/controls.
  UiModel — immutable snapshot без методов, mutable-полей и вычисляемых getters.
- В `@Composable` и пакетах `uimodel` запрещены `&&`, `||`, `!`, `!in`, `!is`,
  вызовы/ссылки `not/and/or/xor`. Обычная отрисовка через `if`/`when` разрешена.
  UI-переключатель — `MutableState<Boolean>.toggle()`; не маскируй правило через `== false`.
- Существующий публичный API сохраняется; новые Boolean в публичных UiModel, пустые
  двухсостоянийные замены и nullable hidden bits запрещены.
- `./gradlew checkComposeNoBooleanLogic` входит в `detekt`/CI. Точный исходный долг
  `config/compose/boolean-logic-baseline.tsv` только сокращается, без новых исключений.

## Проверки

Для бага/нового поведения: различающий тест → RED по нужной причине → реализация → GREEN.
Для чистого рефакторинга сначала запусти существующие тесты; проверь выделенные границы
через production-вход. Тест не должен повторять реализацию или открывать внутренности ради проверки.
Корутинные тесты — kotlin.test + runTest, виртуальное время и наблюдаемые сигналы; без sleep/polling.
Подробности: [testing-strategy](skills/testing-strategy/SKILL.md).

Команды (из корня):

```sh
./gradlew :actron-core:jvmTest :actron-core:apiCheck
./gradlew ktlintCheck detekt
./gradlew :nullability-guard:checkPolicy
# При изменении общей логики также доступны:
./gradlew :actron-core:jsNodeTest :actron-core:wasmJsNodeTest :actron-core:iosSimulatorArm64Test
```

Для других модулей замени `actron-core`; проверяй затронутых потребителей.
`checkNullability` включает компиляции всего проекта и существенно тяжелее source guard.
Полный API/ABI-контур — `./gradlew apiCheck`; граница debug — `./gradlew checkDebugGraph`.
Мутационного раннера здесь пока нет: не обещай TDD+M и не называй M пройденным.
Подключение раннера — отдельное изменение; полезные различающие сценарии нужны уже сейчас.

ktlint отвечает за формат, Detekt — smells/bugs/complexity. Подробности:
[static-analysis](skills/static-analysis/SKILL.md). Baselines — точный существующий долг,
только сокращение; не добавляй suppress/exclude и не поднимай порог ради зелёной проверки.
Зелёный линтер не доказывает правильное распределение ответственности.

## Блокеры

Диагностируй причину, не повторяй одну гипотезу и не ослабляй проверки. Верхний бюджет
одного блокера — 12 разных гипотез либо 180 минут активной работы; затем остановись.
Отсутствие нужного доступа/артефакта или противоречие требованиям докладывай сразу.
Укажи задачу, попытки и ошибки, конкретную причину, что осталось неизменным,
варианты с ценой и что нужно от пользователя. Разрешённые независимые части продолжай.
Недоступную платформу, тест или инфраструктуру не объявляй проверенными.
